# Einbürgerungstest — картинки к вопросам

13 из 310 вопросов каталога опираются на изображение. В исходных данных
(`backend/data/einburgertest-demo-catalog.json`) у всех тринадцати `image.path = null` — есть
только официальное текстовое описание картинки (`image.descriptionDe`), файлов нет.

Этот документ — реестр: что уже нарисовано, что показывается текстом, и что нужно добыть.

## Как вопрос доходит до учащегося

`backend/src/services/mapEinburgertestQuestion.ts` раскладывает вопрос в одну из трёх форм:

| Форма | Когда | Что видит учащийся |
| --- | --- | --- |
| `media` с реальным `url` | картинка добыта и лежит в `backend/data/images/einburgertest/` | картинка над вопросом |
| `optionImages` с реальными `url` | картинкой является каждый вариант ответа | сетка картинок вместо текстовых вариантов |
| `url: null` + `alt` | картинки нет | официальное описание вместо картинки — блок «Image description» или текст под каждым вариантом |

Третья форма — не заглушка, а рабочий режим: это тот же доступный вариант, который BAMF публикует
для незрячих. Вопросы вида «Bild 1 / Bild 2 / Bild 3 / Bild 4» без картинок были бы неотвечаемы,
поэтому описание разбирается по вариантам (`splitImageDescriptionByOption`) и каждый вариант
получает свой кусок текста.

## Почему остальные не добыты

Wikimedia Commons — основной источник свободных изображений для этого набора — **закрыт
egress-политикой прокси этой среды**: `commons.wikimedia.org` и `upload.wikimedia.org` отвечают
403 на CONNECT. Это ограничение окружения, а не техническая проблема; обходить его нельзя.
Добыть файлы можно с обычной машины и положить в `backend/data/images/einburgertest/`.

Для вопросов 181, 216 и 235 отдельная причина: это защищённые авторским правом фотографии
(и скульптура в случае 216), для которых свободной версии, скорее всего, не существует вовсе.
Их разумно оставить текстовыми навсегда.

## Что считается пригодной картинкой

- Свободная лицензия: CC0, public domain (включая § 5 Abs. 1 UrhG для официальных
  государственных работ), либо CC-BY-SA с указанием авторства в поле `attribution`.
- Файл кладётся в репозиторий (`backend/data/images/einburgertest/`), а не подтягивается по
  внешней ссылке: раздаёт их сам бэкенд через `express.static` по `/static/images`.
- Соответствие описанию проверяется по `image.descriptionDe` этого вопроса — неверно опознанный
  герб или флаг хуже отсутствующей картинки.

Схемы бюллетеней к вопросу 130 — исключение из правила «только добытые файлы»: бюллетень это
диаграмма, всё содержание которой («сколько крестиков в какой колонке») задано официальным
описанием дословно, поэтому четыре SVG нарисованы прямо здесь. Названия партий намеренно
обобщённые («Partei A»), чтобы рисунок нельзя было принять за официальный документ.

## Как добавить картинку

1. Положить файл в `backend/data/images/einburgertest/` (имя — `q<номер>-<что-это>.svg|jpg`).
2. Добавить запись в `EINBURGERTEST_MEDIA_OVERRIDES` в
   `backend/src/services/mapEinburgertestQuestion.ts` — по `id` вопроса, не по официальному
   номеру (номера у general и bavaria пересекаются):

   ```ts
   'id-вопроса': {
     media: { kind: 'image', url: `${IMG}/q70-heinemann-schmidt.jpg`, alt: '…', attribution: '…' },
   }
   // либо, если картинкой является каждый вариант ответа:
   'id-вопроса': { optionImages: [ /* по одной записи на вариант, в порядке ответов */ ] },
   ```

3. Обновить таблицу выше и `sourcedIds` в `mapEinburgertestQuestion.test.ts`.
4. Прогнать `npm test` в `backend/` — тест проверяет, что каждый упомянутый файл существует.
5. Перезалить контент: `npm run import:einburgertest` с `DATABASE_URL` целевой базы.
