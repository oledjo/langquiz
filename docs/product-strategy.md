# Repzy — Стратегия продукта

**Дата:** 2026-08-21
**Основание:** аудит кода `oledjo/langquiz` (`master` @ `928f318`) и `oledjo/Repzy-Mobile` (`main` @ `09aa89e`).
**Статус:** предложение к решению. Рыночные оценки помечены как гипотезы — они не выводятся из кода.

---

## 1. Главный вывод

Технически продукт сильнее, чем выглядит его позиционирование. За полгода собран рабочий движок
интервального повторения: FSRS-6 через референсную `ts-fsrs`, идемпотентные записи ответов,
per-deck прогресс, exam mode с квотами по фасетам, аутентификация, аналитика, ретеншн-письма,
RLS-миграция, CI с тестами и мобильная обёртка на Capacitor. Это не прототип — это платформа.

Проблема не в коде. Проблема в том, что **репозиторий содержит три разных продукта одновременно**, и
ни один из них не доведён до состояния, где у него есть пользователь, готовый платить:

1. **LangQuiz** — приложение для изучения немецкого (438 вопросов в бандле, маркетинговый сайт про
   Goethe A2 и артикли);
2. **Reps/Repzy** — субъектно-нейтральная UGC-платформа «колод» («learn anything, one deck at a
   time») — при этом API создания колоды не существует: `backend/src/routes/decks.ts` содержит
   только два `GET`;
3. **Einbürgerungstest** — 310 импортированных вопросов официального теста на гражданство ФРГ, с
   русскими переводами, картинками и настроенным экзаменом 33/17.

Третий — единственный, у которого есть срочная потребность, дедлайн у пользователя, готовность
платить и **конечный объём контента**. Первые два требуют бесконечного производства контента и
конкурируют с Duolingo, Anki и Quizlet.

**Рекомендация: сузиться до Einbürgerungstest как до клина (wedge), а «платформу колод» строить
потом — экзамен за экзаменом, а не как generic UGC.** Всё остальное в этом документе следует из
этого решения.

## 3. Диагноз: шесть мест, где продукт теряет

### D1. Гостевой режим сломан — верхушка воронки пустая

`backend/src/routes/decks.ts:8` — `decksRouter.use(requireAuth)`. Гость получает 401 на
`GET /api/decks`, и `HomePage` показывает ему пустой экран («No decks available yet»). При этом
весь смысл guest-режима, зафиксированный в core-спеке («на UGC-платформе посетитель должен
попробовать колоду до регистрации»), — именно в этом экране.

То же для `GET /api/exercises` — тоже за `requireAuth`, поэтому гость видит только вопросы из
бандла и не может открыть **ни одну** колоду, включая Einbürgerungstest.

Практический эффект: цель из `launch-readiness.md` «visitor → signup ≥ 4%» недостижима, потому что
посетителю нечего попробовать. Это баг №1 по влиянию на бизнес, и чинится он парой строк.

### D2. Контент-конвейер не масштабируется и небезопасен

- `POST /api/exercises/bootstrap` (`routes/exercises.ts:180`) закрыт только `requireAuth`, без
  проверки роли и без валидации содержимого, и делает `UPSERT` в **глобальную** таблицу
  `exercises` по `exercise_id`. Любой зарегистрированный пользователь может перезаписать
  официальный контент — включая вопросы Einbürgerungstest — для всех остальных.
- Сеять контент в базу решает **клиент**: `frontend/src/hooks/useExercises.ts` при каждом входе
  сравнивает бандл с базой и догружает недостающее чанками по 50. Это делает браузер случайного
  пользователя частью инфраструктуры доставки контента.
- Bootstrap не проставляет `deck_id`, поэтому такие строки не принадлежат ни одной колоде.
- Ядро core-спеки — «`exerciseRegistry` и `import.meta.glob` удаляются» — не выполнено:
  `frontend/src/registry/exerciseRegistry.ts` жив, контент по-прежнему компилируется в бандл.
- Пользовательский контент создаётся так: пользователь копирует промпт из
  `ImportExercisesModal.tsx` в ChatGPT, вставляет JSON обратно. Генерация происходит **вне
  продукта** — то есть самая ценная часть цепочки отдана наружу бесплатно.

### D3. Мобильный клиент — форк, а не сборка

`Repzy-Mobile/frontend/src` — физическая копия фронтенда, не сабмодуль. Разошлось уже **32 файла**:
в мобильной копии есть французский контент (`fr-*`), которого нет в основном репозитории, а в
основном — `StudyStatistics.tsx`, `QuestionBreakdown.tsx`, `untriedExercises.ts`, которых нет в
мобильной. Каждая новая фича теперь стоит двух реализаций, и расхождение растёт монотонно.

### D4. Монетизации нет ни в каком виде

Ни фича-флагов, ни entitlement-модели, ни абстракции провайдера — при том, что
`further-improvements-plan.md` относит это к P2 «12+ недель». Для продукта, у которого нет ни
одного платящего пользователя, порядок обратный: сначала проверяется, платят ли, потом строится
всё остальное.

### D5. Самый ценный актив в данных не показывается

В импорте Einbürgerungstest лежат `translations.ru` (промпт, варианты, объяснение) и `media` — и
ни один компонент их не рендерит. Это зафиксировано как осознанный non-goal в спеке импорта. Но
именно двуязычность — то, чего нет у бесплатного официального тренажёра BAMF, и то, что нужно
целевой аудитории, которая по определению ещё не владеет немецким свободно.

### D6. Дистрибуции нет

`MarketingSite.tsx` — восемь заглушек статей с заголовками, но без текстов. Домен не куплен
(`docs/superpowers/plans/2026-08-14-repzy-rebrand.md`, Task 0 — не выполнен), продакшн живёт на
`langquiz.onrender.com`, то есть SEO-вес копится на чужом домене под старым брендом. Контент-план
на 2 гайда в неделю не исполняется.

## 4. Выбор ставки

| | A. Einbürgerungstest | B. Изучение немецкого | C. Платформа колод (UGC) |
|---|---|---|---|
| Объём контента | **Конечный:** 300 общих + по 10 на землю | Бесконечный | Бесконечный, чужими руками |
| Уже сделано | 310 вопросов, exam mode, картинки, RU-переводы | 438 вопросов, A1–C2 частично | Модель данных есть, API создания колод нет |
| Срочность у пользователя | **Дедлайн:** запись на тест, подача на гражданство | Нет | Нет |
| Готовность платить | **Высокая:** цена ошибки — пересдача и месяцы ожидания | Низкая (рынок приучен к freemium) | Около нуля |
| Конкуренты | Бесплатный тренажёр BAMF, десяток одинаковых бесплатных приложений | Duolingo, Babbel, Seedlang, Anki | Anki, Quizlet, Brainscape |
| Стоимость выхода на рынок | Низкая: узкие каналы, ясные ключевые запросы | Очень высокая | Очень высокая |
| Реалистично для соло-разработчика | **Да** | Нет | Нет |

**Решение: A.**

Ключевой аргумент — не размер рынка, а то, что при ставке A **проблема контента становится
закрытой**. Официальный каталог конечен: 300 общих вопросов плюс 10 на каждую из 16 федеральных
земель. Сейчас импортированы только Бавария. Дописать оставшиеся 15 земель — это ~150 вопросов
разовой работы, после которой продукт покрывает предмет **на 100%**, а конкурент не может
предложить «больше контента» в принципе. Ни в одной другой ставке такого потолка нет.

### Позиционирование

> **Repzy — сдать Einbürgerungstest с первого раза, готовясь по 10 минут в день на родном языке.**

**ICP (ядро):** взрослый, живёт в Германии 5+ лет, подаёт на гражданство, немецкий на уровне
B1 максимум, готовится 2–8 недель, боится провалить и потерять месяцы. Первый языковой сегмент —
русскоязычные, потому что переводы уже лежат в данных и не требуют затрат.

**Почему за это платят при наличии бесплатного тренажёра BAMF:** бесплатный тренажёр даёт случайные
вопросы и не отвечает на единственный вопрос, который волнует пользователя — «я уже готов или
ещё нет». Repzy продаёт не вопросы, а **уверенность и экономию времени**: FSRS ведёт по слабым
местам, прогноз готовности основан на реальной модели памяти, пробный экзамен воспроизводит формат
33/17 с квотой по вашей земле, объяснения — на родном языке.

**Расширение TAM без затрат на контент:** тот же каталог используется в тесте «Leben in Deutschland»
(нужен для ПМЖ и по итогам интеграционных курсов). Один и тот же продукт обслуживает две аудитории,
разница только в копирайте лендинга.

## 5. Стратегия по горизонтам

### H1 — Клин (0–6 недель). Цель: первые 100 платящих

Гипотеза к проверке: **люди, готовящиеся к Einbürgerungstest, заплатят €10 за уверенность в сдаче.**

Скоуп:
1. Починить гостевой доступ: `GET /api/decks` и `GET /api/exercises` доступны без токена для
   `origin = 'official'`; гость проходит 10 вопросов и упирается в регистрацию.
2. Дописать 15 недостающих федеральных земель в каталог; выбор земли — при первом входе,
   он же управляет квотой экзамена.
3. Показать `translations.ru`: тумблер «показать перевод» на карточке вопроса и в объяснении.
   Данные уже есть — это чисто UI-работа.
4. Экран «Готовность к экзамену»: процент готовности из FSRS-стабильности, число освоенных
   вопросов из 310, прогноз даты готовности, кнопка «Пробный экзамен».
5. Один платный шлюз: бесплатно — 100 вопросов и один пробный экзамен; дальше разовая покупка.
6. Лендинг под запрос, а не гайды: `/einbuergerungstest` на собственном домене, с бесплатным
   пробным тестом на самой странице.

**Definition of done H1:** незалогиненный человек с телефона проходит 10 вопросов, видит свой
результат, регистрируется, платит, сдаёт пробный экзамен по своей земле — и всё это отслеживается
событиями аналитики от `session_started` до покупки.

Заморожено в H1: французский и испанский контент, UGC-импорт как публичная фича, голосование за
вопросы, очередь шаринга, блог-гайды, любая работа над «платформой».

### H2 — Монетизация и удержание (6–16 недель)

- Ретеншн-цикл под дедлайн: пользователь вводит дату экзамена, продукт строит план и шлёт письма
  «сегодня 18 вопросов, до экзамена 12 дней» (инфраструктура писем уже готова).
- Второй язык интерфейса и объяснений: турецкий или арабский — по данным о трафике. Стоимость —
  перевод 310 объяснений, не новый предмет.
- Мобильные приложения в сторах (клин мобильный: люди учатся в S-Bahn). Оплата — на вебе, чтобы
  не отдавать 15–30% сторам.
- Слияние репозиториев (см. §9, P0) — иначе стоимость каждой фичи удваивается именно здесь.
- Первые каналы: сообщества экспатов в Германии, субреддиты, телеграм-чаты, SEO по узким запросам
  («einbürgerungstest вопросы на русском», «leben in deutschland test üben»).

**Гейт H2 → H3:** ≥300 платящих и конверсия из активированного пользователя в покупку ≥8%. Если не
достигнуто — проблема в клине, а не в отсутствии второго предмета; расширяться нельзя.

### H3 — Движок экзаменов (4–9 месяцев)

«Платформа колод» возвращается — но не как generic UGC, а как **фабрика однотипных экзаменов**.
Движок уже субъектно-нейтрален: колода + фасеты + `examConfig` + FSRS. Каждый следующий предмет —
это контент и лендинг, а не новый код:

- теория на водительские права в Германии (Führerschein) — конечный официальный каталог, платящая
  аудитория, тот же паттерн;
- тесты на гражданство/интеграцию других стран;
- профессиональные сертификации с фиксированным банком вопросов.

Здесь же уместна AI-генерация колод **внутри** продукта (сейчас пользователь делает это руками в
ChatGPT) — как инструмент оператора для быстрого создания новых предметов, а затем как фича для
пользователей.

## 6. Монетизация

**Модель: разовая покупка, не подписка.**

Подписка плохо ложится на продукт с дедлайном: пользователь готовится 2–8 недель и уходит навсегда,
сдав экзамен. Подписка в такой схеме порождает возвраты, отмены и негатив; разовая покупка совпадает
с ментальной моделью «я покупаю сдачу экзамена».

| | Бесплатно | Repzy Pass — €9.99 разово |
|---|---|---|
| Вопросы | 100 из 310 | Все 310 + вопросы вашей земли |
| Пробный экзамен | 1 | Без ограничений |
| Переводы объяснений | Первые 20 вопросов | Все |
| Интервальные повторения | Да | Да |
| Прогноз готовности | Только общий процент | Полный, с датой готовности и слабыми темами |
| Напоминания по плану | Нет | Да |

Гипотезы к проверке (не факты): цена €9.99 против €14.99 — A/B на лендинге до постройки биллинга;
конверсия «активированный → платящий» 5–10% для дедлайн-продукта.

Реализация — минимальная: Stripe Payment Link + вебхук, одна колонка `users.entitlement`, один
хук `useEntitlement` на фронте. Никакой абстракции провайдера и никакого entitlement-фреймворка,
пока не доказано, что платят.

## 7. Метрики

**North Star: число пользователей, достигших «готов к экзамену»** (≥80% каталога в состоянии
FSRS-review со стабильностью выше порога). Она измеряет обещание продукта, а не активность.

Воронка на уже существующих событиях (`docs/launch-readiness.md`, `backend/src/routes/events.ts`):

| Шаг | Событие | Цель H1 |
|---|---|---|
| Визит → первый ответ (гость) | `session_started` → `question_answered` | ≥55% |
| Первый ответ → регистрация | `auth_signup_success` | ≥25% |
| Регистрация → завершённая сессия | `session_completed` | ≥45% |
| Активация → покупка | *(новое)* `purchase_completed` | ≥5% |
| D7-возврат | `day7_retained` | ≥25% |
| Готовность к экзамену | *(новое)* `exam_ready_reached` | ≥15% от платящих |

Добавить два события: `purchase_completed` и `exam_ready_reached`. Остальное уже инструментировано.

## 8. Что заморозить или удалить

| Фича | Решение | Почему |
|---|---|---|
| Голосование за вопросы (`exercise_votes`) | Удалить из UI, оставить таблицу | Нет аудитории, для которой это сигнал |
| Очередь шаринга и модерация UGC | Заморозить | Обслуживает несуществующий UGC-поток |
| Импорт JSON пользователем | Спрятать в «Для преподавателей» | Мощно, но не для ICP; поддержка дороже пользы |
| Испанский и французский контент | Заморозить | 3 файла контента — не продукт, а распыление |
| Гайды на `/learn/*` | Заменить одним лендингом под запрос | 8 пустых заглушек хуже, чем одна работающая страница |
| Немецкая грамматическая колода | Оставить как бесплатный бонус | Уже оплачена работой, поддерживает SEO, но не фокус |
| `import.meta.glob` + `exerciseRegistry` | Удалить (см. §9) | Два пути доставки контента вместо одного |

## 9. Технический бэклог под эту стратегию

### P0 — до любого маркетинга

1. **Закрыть `POST /api/exercises/bootstrap`** — требовать роль `admin`
