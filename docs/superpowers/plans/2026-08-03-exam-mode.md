# Exam Mode — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real exam-taking flow — question selection by facet quota, free navigation with no
per-question feedback, and end-of-exam scoring — reachable from Deck Detail for any deck whose
`studyModes` includes `'exam'`. This is Plan 6 of the Reps platform rewrite (see
`docs/superpowers/specs/2026-08-02-reps-platform-core-design.md`); Plans 1–5 are merged to `master`.

**The data-shape gap this plan works around, stated plainly:** `Deck.examConfig.quotas` (built in
Plan 1) describes quotas as generic `facetKey`/`facetValue` pairs — e.g. `scope`/`general` for the
Einbürgerungstest deck this is ultimately for. But the exercise data actually stored in Postgres and
returned by `fetchExercisesForDeck` (Plan 5) is still in the old bundle-authored `Exercise` shape,
with hardcoded `topic`/`subtopic`/`language`/`level`/`group` fields — there is no `scope` field
anywhere in real data today, and won't be until the Einbürgerungstest import (a separate, later plan)
loads content that actually has it. **No deck in this codebase has `examConfig` set today.** This
plan builds the exam *mechanics* — selection-by-quota, the exam screen, scoring, backend support for
exam submissions not moving spaced-repetition intervals — as real, working, tested code, using
`toDeckExercise` (built in Plan 1, unused until now) to derive facets from the existing exercise
shape. It does not, and cannot yet, verify quota selection against real `scope`-based exam data,
because none exists. That verification happens naturally once the Einbürgerungstest import plan loads
a deck with a real `examConfig`.

**Non-goals (explicitly deferred):**
- Any real, committed exam configuration for an actual deck — that's the Einbürgerungstest import's
  job, once it has content with meaningful facets to quota against.
- Time limits (`ExamConfig.timeLimitMinutes` exists as a field but this plan doesn't enforce it).
- Restoring a previously-selected answer's visual state when navigating back to an already-answered
  question mid-exam — see the "Known limitation" note in Task 4.
- Touching `QuizCard`, `QuizSession`, or `useExerciseSession` (practice mode) at all — exam mode is
  built as an independent screen reusing only the lower-level, already-shared
  `getQuestionComponent`/`validateAnswer` pieces.

**Architecture:** `POST /api/progress` gains an optional `mode: 'practice' | 'exam'` field (default
`'practice'`, fully backward compatible); when `mode === 'exam'`, the row is still inserted into
`progress` (so it counts toward stats) but the `user_review_schedule` SM-2 update is skipped
entirely. `frontend/src/api/progressApi.ts`'s `postResult` gains a matching optional `mode` parameter.
A new pure function `frontend/src/lib/examQuestionSelection.ts` selects exercises per
`ExamConfig.quotas`, using `toDeckExercise(...).facets` purely as a facet-lookup (the exercises
themselves stay in their original `Exercise` shape throughout, since the rendering layer —
`getQuestionComponent` — expects that shape, not `AnyDeckExercise`). A new page
`frontend/src/pages/ExamSessionPage.tsx` fetches the deck and its exercises (reusing `useDeck`/
`useDeckExercises` from Plan 5), selects the exam set, and renders a free-navigation multi-question UI
with a submit-and-score flow. `DeckDetailPage` gains a "Start exam" button gated on
`deck.studyModes.includes('exam')` — and, closing a gap Plan 5's code review flagged but left as a
noted follow-up, the existing "Start practicing" button gets the equivalent
`deck.studyModes.includes('practice')` gate at the same time, since both buttons need the same kind
of check and doing it once is cheaper than doing it twice.

**Tech Stack:** React 19, react-router-dom 7, Express 5, Vitest (frontend and backend) — all already
in place from Plans 1–5.

**Plan sequence (updated):**
1. Domain model foundation & brand rebrand — done (merged to `master`).
2. Backend decks table & content storage — done (merged to `master`).
3. Frontend routing foundation — done (merged to `master`).
4. Library and Deck Detail screens — done (merged to `master`).
5. Deck-scoped study sessions — done (merged to `master`).

7. Deck-scoped progress dashboard.
8. Einbürgerungstest import (separate spec) — the first deck that will actually exercise this plan's

- [ ] **Step 3: Implement the selection function**

Create `frontend/src/lib/examQuestionSelection.ts`:

```ts
import { toDeckExercise } from './legacyExerciseMapper'
import type { ExamConfig } from '../types/deck'
import type { Exercise } from '../types/exercise'

function shuffle<T>(items: T[]): T[] {
  const copy = [...items]
  for (let i = copy.length - 1; i > 0; i -= 1) {
    const j = Math.floor(Math.random() * (i + 1))
    ;[copy[i], copy[j]] = [copy[j], copy[i]]
  }
  return copy
}

/**
 * Picks exercises to fill an exam's facet quotas (see ExamConfig.quotas). Operates on the
 * original bundle-authored Exercise shape throughout — toDeckExercise is used only as a
 * facet-lookup helper for matching, not to convert the exercises themselves, since the
 * rendering layer (getQuestionComponent) expects the original Exercise shape.
 */
export function selectExamQuestions(exercises: Exercise[], deckId: string, examConfig: ExamConfig): Exercise[] {
  const remaining = [...exercises]
  const selected: Exercise[] = []

  for (const quota of examConfig.quotas) {
    const matches = remaining.filter(
      (exercise) => toDeckExercise(exercise, deckId).facets[quota.facetKey] === quota.facetValue
    )
    const picked = shuffle(matches).slice(0, quota.count)
    selected.push(...picked)
    for (const pick of picked) {
      const index = remaining.indexOf(pick)
      if (index >= 0) remaining.splice(index, 1)
    }
  }

  return shuffle(selected).slice(0, examConfig.questionCount)
}
```

### Task 4: `ExamSessionPage`

**Known limitation, stated up front:** `SelectionQuestion`/`MultiSelectQuestion`/`FreeTypeQuestion`
(the components `getQuestionComponent` returns) are uncontrolled — each owns its own `useState` for
the current selection and has no prop to restore a previously-given answer. This plan does not modify
them, because they're shared with practice mode (`QuizCard`/`QuizSession`) and changing their prop
contract risks a regression there for a benefit that's exam-only. The practical effect: navigating
back to an already-answered question during an exam shows a blank/unanswered question UI, even though
the answer **is** correctly retained in `ExamSessionPage`'s own state and **will** be scored correctly
at submission. To avoid this reading as silently losing the user's work, the question navigator (Step
3 below) marks answered questions with a visible indicator, so the retained-but-not-displayed state is
at least discoverable.

Create `frontend/src/pages/ExamSessionPage.tsx`:

```tsx
import { useMemo, useState } from 'react'
import { Link, useParams } from 'react-router-dom'
import { getQuestionComponent } from '../components/questions/questionRegistry'
import { useDeck } from '../hooks/useDecks'
import { useDeckExercises } from '../hooks/useDeckExercises'
import { selectExamQuestions } from '../lib/examQuestionSelection'
import { postResult } from '../api/progressApi'
import { validateAnswer } from '../validators/answerValidator'
import type { UserAnswer } from '../types/exercise'

export function ExamSessionPage() {
  const { slug } = useParams<{ slug: string }>()
  const { deck, loading: deckLoading, error: deckError } = useDeck(slug ?? '')
  const { exercises, loading: exercisesLoading, error: exercisesError } = useDeckExercises(deck?.id ?? '')

  const [currentIndex, setCurrentIndex] = useState(0)
  const [answers, setAnswers] = useState<Record<string, UserAnswer>>({})
  const [submitting, setSubmitting] = useState(false)
  const [score, setScore] = useState<{ correct: number; total: number } | null>(null)

  const examQuestions = useMemo(() => {
    if (!deck?.examConfig || exercises.length === 0) return []
    return selectExamQuestions(exercises, deck.id, deck.examConfig)
    // eslint-disable-next-line react-hooks/exhaustive-deps -- deliberately NOT re-selecting on
    // every exercises/deck reference change (both are stable after their initial load in this
    // page's lifecycle); re-running this on every render would reshuffle the exam mid-attempt.
  }, [deck?.id])

  const loading = deckLoading || (Boolean(deck) && exercisesLoading)
  const error = deckError ?? exercisesError
  const canOfferExam = Boolean(deck?.examConfig) && Boolean(deck?.studyModes.includes('exam'))

  const handleSubmit = async () => {
    setSubmitting(true)
    let correctCount = 0
    for (const exercise of examQuestions) {
      const answer = answers[exercise.id]
      if (!answer) continue
      const result = validateAnswer(exercise, answer)
      if (result.correct) correctCount += 1
      await postResult(exercise.id, result.correct, result.correct ? 'good' : 'again', 'exam')
    }
    setScore({ correct: correctCount, total: examQuestions.length })
    setSubmitting(false)
  }

  if (loading) return <p className="text-sm text-slate-400">Loading…</p>

  if (!deckLoading && !deckError && !deck) {
    return <p className="text-sm text-slate-500">Deck not found.</p>
  }

  if (error) {
    return <div className="rounded-xl border border-red-100 bg-red-50 p-4 text-sm text-red-600">{error}</div>
  }

  if (!deck) return null

  if (!canOfferExam) {
    return (
      <div className="space-y-4">
        <Link to={`/deck/${deck.slug}`} className="text-sm font-semibold text-blue-700 hover:text-blue-800">
          ← {deck.title}
        </Link>
        <p className="text-sm text-slate-500">This deck does not offer an exam.</p>
      </div>
    )
  }

  if (score) {
    const passed = score.correct >= (deck.examConfig?.passingScore ?? 0)
    return (
      <div className="space-y-4">
        <div className="rounded-2xl border border-gray-100 bg-white p-6 text-center shadow-sm">
          <p className="text-3xl font-bold text-slate-900">
            {score.correct} / {score.total} correct
          </p>
          <p className={['mt-2 text-lg font-semibold', passed ? 'text-emerald-600' : 'text-red-600'].join(' ')}>
            {passed ? 'Passed' : 'Not passed'}
          </p>
          <Link
            to={`/deck/${deck.slug}`}
            className="mt-4 inline-block rounded-xl bg-blue-600 px-5 py-3 text-sm font-semibold text-white hover:bg-blue-700"
          >
            Back to deck
          </Link>
        </div>
      </div>
    )
  }

  const currentExercise = examQuestions[currentIndex]
  const QuestionComponent = currentExercise ? getQuestionComponent(currentExercise.type) : null

  return (
    <div className="space-y-4">
      <Link to={`/deck/${deck.slug}`} className="text-sm font-semibold text-blue-700 hover:text-blue-800">
        ← {deck.title}
      </Link>

      <div className="flex flex-wrap gap-2">
        {examQuestions.map((exercise, index) => (
          <button
            key={exercise.id}
            onClick={() => setCurrentIndex(index)}
            className={[
              'h-8 w-8 rounded-full text-xs font-semibold transition-colors',
              index === currentIndex
                ? 'bg-blue-600 text-white'
                : answers[exercise.id]
                  ? 'bg-emerald-100 text-emerald-700'
                  : 'bg-slate-100 text-slate-500',
            ].join(' ')}
          >
            {index + 1}
          </button>
        ))}
      </div>

      <p className="text-sm text-slate-500">
        Question {currentIndex + 1} of {examQuestions.length}
      </p>

      {currentExercise && QuestionComponent && (
        <div className="rounded-2xl border border-gray-100 bg-white p-6 shadow-sm">
          <h2 className="text-xl font-semibold text-gray-800">{currentExercise.prompt}</h2>
          <div className="mt-4">
            <QuestionComponent
              exercise={currentExercise}
              onAnswer={(answer: UserAnswer) =>
                setAnswers((prev) => ({ ...prev, [currentExercise.id]: answer }))
              }
              disabled={submitting}
              validationResult={null}
            />
          </div>
        </div>
      )}

      <div className="flex items-center justify-between">
        <div className="flex gap-2">
          <button
            onClick={() => setCurrentIndex((i) => Math.max(0, i - 1))}
            disabled={currentIndex === 0}
            className="rounded-xl border border-slate-200 bg-white px-4 py-2 text-sm font-semibold text-slate-600 disabled:cursor-not-allowed disabled:opacity-50"
          >
            Previous
          </button>
          <button
            onClick={() => setCurrentIndex((i) => Math.min(examQuestions.length - 1, i + 1))}
            disabled={currentIndex === examQuestions.length - 1}
            className="rounded-xl border border-slate-200 bg-white px-4 py-2 text-sm font-semibold text-slate-600 disabled:cursor-not-allowed disabled:opacity-50"
          >
            Next
          </button>
        </div>
        <button
          onClick={handleSubmit}
          disabled={submitting}
          className="rounded-xl bg-blue-600 px-5 py-3 text-sm font-semibold text-white hover:bg-blue-700 disabled:cursor-not-allowed disabled:opacity-70"
        >
          Submit exam
        </button>
      </div>
    </div>
  )
}
```

`examQuestions` is computed via `useMemo` keyed only on `deck?.id` (not `exercises`, which would be
unstable across renders and would reshuffle the exam every time `useDeckExercises` re-runs — it only
re-runs once in this page's lifecycle per Plan 5's Task 2 fix, but keying on the primitive `deck.id`
is the more robust choice regardless). The exam is selected once, when the deck first becomes
available, and stays fixed for the rest of the attempt.

## Implementation Notes (added after execution)

Real deviations from this plan's literal sample code, found during execution and code review:

- **Task 4 — `useMemo` timing bug in the sample code.** The plan's sample selected `examQuestions` via
  `useMemo(..., [deck?.id])`. On the very render where `deck?.id` first becomes truthy,
  `useDeckExercises` (keyed on the same `deck?.id`) hasn't resolved yet in that same commit, so
  `exercises` is still `[]` — the memo would compute against an empty array and then never
  recompute, permanently stranding the exam at 0 questions. Fixed by replacing the `useMemo` with a
  `useState`/`useEffect` pair that only sets `examQuestions` once both `deck.examConfig` is present
  AND `exercises.length > 0`, guarded by an `examQuestions.length > 0` early return so it never
  reselects mid-attempt.
- **Task 4 — test flakiness from an unseeded shuffle.** `selectExamQuestions` uses real
  `Math.random()`, so the plan's test (which clicks specific answer buttons assuming a fixed question
  order) was genuinely flaky (~50% pass rate observed). Fixed with
  `vi.spyOn(Math, 'random').mockReturnValue(0)` in `beforeEach`, which makes the Fisher-Yates shuffle
  deterministic.
- **Task 4 — passing-score fixture contradicted the plan's own scoring formula.** The plan's sample
  `score.correct >= (deck.examConfig?.passingScore ?? 0)` combined with the plan's own test fixture
